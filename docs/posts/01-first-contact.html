First contact with the Frame API

Frame started out as a no-code platform for 3D, browser-based collaboration spaces. It now also has a small REST API, and we wanted to know how much an AI agent could do with it.

Frame's tutorial points to a Swagger page. Behind that page is an OpenAPI spec, "External Automation Api" v0.66.3, served from https://api.framevr.io. The spec lists 15 operations across five areas: frame settings, members, admins, assets and scenes. Every call needs a bearer token, which is your API key from the Profile panel. Without one, the API returns 401.

The asset list shows how far you can go. Alongside images, models and videos it covers spawn spots, voice zones, streaming screens, polls, shaders, whiteboards, remote browsers, NPCs and agents. So you can script the room, as well as its access list.

What we did: ran four read-only calls against our own space, letscollaborate, and every one returned 200. We changed nothing.

What we didn't do: publish anything from inside the space. This log only records status codes and the shape of the API.

Caveats: the tutorial mentions sending chat to the whole Frame, but the v0.66.3 spec has no chat endpoint. Frame also says the API "may be limited to paid plans in the future".

Next, we'll set up a sandbox Frame and place the first objects in it through the API.
